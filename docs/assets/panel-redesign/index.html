What changed against today's panel

  • Overview shows verdicts, Health shows tables. Process lists, socket paths and interface counters moved to Server › Health, one click from each card.
  • Every page is one of three layouts: a list (form on top, table below), a detail page (sticky side menu + numbered boxes), or a form page (boxes in equal columns). No page picks its own width.
  • Own password is Account, instance defaults are Settings. Export sits with the domain, import with Backup, and each links to the other.
  • Queues are tables, not a postqueue -p dump — this needs postqueue -j parsing. The inbound queue is the same queue filtered by recipient domain.
  • Confirm pages say what will be lost as a list, beside a hint for the usual alternative (export before delete).
  • Own components on top of Bulma: postmark, perforated edge, numbered box head, health card, DNS record block, facts grid, timeline, log pane. The mockup's theme.css is about 200 lines.
  • panel/build.py wraps the fragments in panel/src/ with the shared navbar; the built pages are committed, so nothing has to be run to view them.

Stage 1 · three directions on three key screens

Kept for the record: Overview, an outbound domain and sign-in, drawn three ways.

Shared by all three

  • Navigation by mail direction. Overview · Outbound (Domains, Log, Queue, DMARC reports) · Inbound (Domains, Log, Queue) · Server (System log, Backup, Users, Settings). Account, Help and Sign out live with the user name. Eleven flat entries become four groups.
  • One block per DNS record. Today "DNS status" and "records to publish" show every host twice. Here a record is one block: its status, what to publish, and — only on a mismatch — what DNS holds now.
  • The domain page stops being nine cards. DNS and applications are the page; limits, report address, export and delete are "rarely changed" and sit behind one click.
  • Applications are a table; editing one is its own form page instead of a three-column panel inside a list row.
  • Brand carriers stay: the stamp, brick, IBM Plex. No inline style or script in any mockup.

Open points

  • Icons in B come from Tabler Icons (MIT) through its webfont for the mockup; the panel would vendor only the used glyphs as an SVG sprite.
  • Inbound log rides on the agreed inbound-antispam-panel journal; Inbound queue is a new filter over the one Postfix queue and needs its own roadmap row.
  • Dark scheme and the narrow-screen shell are not drawn at this stage; all three libraries ship both.
  • The earlier panel-ui experiment and panel-redesign.md are superseded by whichever direction is accepted.
